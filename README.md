# LanScope

SwiftUI + Network.framework 的 iOS 局域网主机发现原型。无后端、无第三方依赖。最低 iOS 17，使用 Xcode 15 或更新版本。

## 已实现

- 每次启动 App 创建扫描页面时，自动识别一次当前 Wi-Fi 的 IPv4 地址和实际子网掩码，填入对应 CIDR；用户可直接修改输入框，无需切换模式。支持私有地址和链路本地地址。
- 单次最多 1024 个地址（最宽 /22）；排除常规网段的网络地址和广播地址，正确处理 /31 和 /32。
- 每次开始扫描时重新读取本机 Wi-Fi IPv4 地址，Ping 筛选和直接 TCP 两种模式均在发包前排除本机；进度和历史中的总数以排除后的地址数为准。仅包含本机的 /32 会直接结束并提示没有其他地址。
- 扫描目标下方提供“高级设置”弹窗，默认开启“只扫描 ping 成功的设备”；可自定义 TCP 端口（默认 21、22、80、443、445、548、631、2049、3000、3306、3389、5000、5001、5432、5900、6379、8000、8080、8081、8123、8443、9000、9090、32400，共 24 个），覆盖常见文件共享、远程管理、打印、数据库及 NAS/自建 Web 服务。以逗号或空格分隔，范围 1–65535，自动去重。点击保存后通过 UserDefaults 持久化到本机，取消不保存。已保存的配置保持不变，可点击“恢复默认设置”后保存以使用新默认列表；端口越多，扫描耗时越长。这里只探测 TCP，不包含同端口号的 UDP 服务。
- 仅走 Wi-Fi，同时最多处理 24 个地址，每台主机最多并发探测 4 个 TCP 端口；端口探测完成后最多并发识别 4 个 Web 协议端点，HTTP/HTTPS 可同时探测。TCP、HTTP/HTTPS 及页面读取共用全局最多 64 个连接，排队不计入超时；ICMP 和单个 TCP 端口的超时均为 1.5 秒。每个地址在端口和 Web 探测全部结束后计入完成进度。默认先发一次 ICMP Echo，只对收到匹配 Echo Reply 的地址检查全部指定 TCP 端口；无回应直接跳过 TCP。关闭 ping 筛选后直接对全部地址检查指定 TCP 端口。
- Ping 成功或 TCP 连接成功/明确拒绝均记录为响应证据。实时结果和历史详情仅展示连接成功的开放端口，分别标注 Ping 与 TCP 耗时；隐藏拒绝连接、未响应、探测错误的端口及空端口占位，旧版单端口历史同样隐藏拒绝连接记录。Ping 成功的设备即使没有响应端口也保留主机和 Ping 结果，完整探测结果仍保存到历史中。
- 实时结果、数字 IP 排序、探测耗时、进度和取消。主机 IP 右侧显示 Ping 耗时，不再单独显示“Ping 成功”或底部发现时间；实时结果与历史详情使用相同布局。
- 进入后台停止扫描；保留当前结果，重新扫描清空。
- 本地扫描历史：扫描完成或已有进度/发现主机的扫描中断后自动保存，保留最近 30 次；按今天、昨天、更早展示，支持查看单次结果及滑动删除。记录网段、起止时间、完成状态、进度、主机响应信息、诊断提示及当次扫描设置；兼容旧版历史。
- 历史记录保存扫描开始时的 Wi-Fi 名称，名称和时间在同一行显示；今天、昨天仅显示时分，更早的记录同时显示日期。旧记录或未取得名称时显示“未记录 Wi-Fi”，不使用查看历史时的网络信息回填。
- 扫描区域标题显示 Wi-Fi 图标和名称，右侧保留设置按钮；前台每 3 秒刷新，返回前台立即刷新，读取失败时仅显示“Wi-Fi”。仅展示名称，不提供设置跳转，也不因名称变化修改扫描网段。首次进入扫描页请求使用期间的定位授权，启用精确位置后可读取 Wi-Fi 名称；不请求或保存位置坐标。拒绝授权或关闭精确位置不影响扫描，但无法显示或记录名称。
- 局域网权限说明、网络错误提示、独立核心单元测试和 macOS CI。

## 在 Mac 上运行

1. 打开 `LanScope.xcodeproj`，选择 `LanScope` scheme。
   签名需包含 `Access WiFi Information` 能力；工程已配置对应 entitlement。手动签名或 TestFlight CI 使用的 App Store provisioning profile 也需包含 `com.apple.developer.networking.wifi-info`，开启能力后重新生成并更新 `BUILD_PROVISION_PROFILE_BASE64`。
2. 在 Signing & Capabilities 中确认 Team。当前 Bundle ID 为 `com.yoonzm.lanscope`，Team ID 为 `6F7QRYSM6W`。
3. 连接 iPhone，按 Xcode 提示启用开发者模式，选择真机并运行。
4. 将 iPhone 连接到测试 Wi-Fi，打开 App 后等待自动填入网段；需要指定范围时，直接编辑 CIDR，例如 `192.168.1.0/24`。
5. 开始扫描并允许局域网访问。首次权限弹窗可能超过探测超时；授权后再次开始即可。拒绝后可在系统设置中打开此 App 的局域网权限。

自动识别使用 Network.framework 提供的 Wi-Fi 接口名称，配合 `getifaddrs` 读取 IPv4 地址及掩码，不假定 /24，也不使用蜂窝或 VPN 接口地址。没有可用 IPv4 或出现多个候选地址时提示手动输入，不回退到示例网段。识别到 /16 等大网段时展示真实范围，但保留最多 1024 个地址的扫描限制，需手动缩小范围。自动识别只填写范围，用户点击“开始扫描”后才发起探测。

### GitHub Actions TestFlight 发布

`.github/workflows/testflight.yml` 在推送 `main` 时自动执行，也支持手动启动。工作流在 macOS 上选择稳定版 Xcode 26 或更新版本，检查 iOS SDK 至少为 26，然后测试、签名归档、导出 IPA 并上传 App Store Connect。仅允许 `main` 分支发布，不向 PR 提供签名材料。上传成功后由 Apple 处理，再交给已启用自动分发的“个人设备自动测试”内部组。IPA 和构建日志保留 7 天；临时钥匙串及密钥在任务结束时清理。

需要在仓库 Settings → Secrets and variables → Actions 配置：

| Secret | 内容 |
|---|---|
| `BUILD_CERTIFICATE_BASE64` | 含私钥的 Apple Distribution `.p12` 文件的 Base64 |
| `P12_PASSWORD` | `.p12` 导出密码 |
| `BUILD_PROVISION_PROFILE_BASE64` | 匹配 `com.yoonzm.lanscope` 的 App Store `.mobileprovision` 的 Base64 |
| `ASC_KEY_ID` | App Store Connect 团队 API 密钥 ID |
| `ASC_ISSUER_ID` | API Issuer ID |
| `ASC_PRIVATE_KEY` | `.p8` 私钥原文（保留换行） |

上述 Secrets 已配置。发布流程串行执行，避免同时上传；失败时可以在 Actions 页面重试。可在仓库 Actions 页的 `TestFlight` 工作流中下载 IPA 或查看上传结果。

应用版本为 `0.1.1`。TestFlight 的 Build 从 `1` 开始，每次新工作流运行自动递增为 `2`、`3` 等，无需手动修改；失败的运行也占用编号，重跑同一次工作流复用原编号。已上传成功后需推送新提交或点击 Run workflow 创建新运行，不能重复上传同一编号。工作流扣除旧版本已执行的 7 次运行，不再添加大数字偏移或重试后缀。`ITSAppUsesNonExemptEncryption=false` 已写入 Info.plist，与当前应用实现一致；若以后加入新的加密功能，应重新评估该声明。

导出限制为 TestFlight 内部测试，不提交外部测试审核或 App Store 审核。App Store 类型的 IPA 不可直接通过“文件”App 安装。不要把证书、私钥或 API key 提交进仓库。

## 结果解释与边界

- 未响应不代表离线。设备可能过滤这些端口、休眠或处于 AP 隔离网络。
- 连接拒绝说明有响应证据，但响应也可能来自防火墙等中间设备。
- Ping 时间为收到 Echo Reply 的往返耗时；每个 TCP 端口单独显示该次连接尝试耗时，两者不能混用。
- 只探测用户指定的 TCP 端口，未扫描端口的状态未知；未响应不能直接判定端口关闭。
- 默认 ping 筛选会漏掉不回应 ICMP 的在线设备，可在高级设置中关闭。ICMP 不可用时明确报错，不静默退回 TCP；首次本地网络授权可能超过 ping 时限，允许后应重新扫描。
- TCP 单个端口失败不会中止整个扫描：明确拒绝连接记为“拒绝连接”，普通超时记为“未响应”，`EPERM` / `EACCES` 记为该端口的“探测错误”并立即继续；其他 `.waiting` 错误允许在 1.5 秒期限内恢复，到期仍未恢复则记为“探测错误”并继续其余端口和地址。界面及历史保留最近一条诊断，错误本身不作为设备在线或离线的证据。
- 自动填写网段仅在扫描页面初始化时尝试一次，不提供重新识别按钮；回到前台、网络变化及开始扫描时均不覆盖输入。识别完成前用户已编辑（包括输入后清空）的内容也会保留。每次开始扫描时另行读取当前 Wi-Fi 接口和本机地址用于排除本机；识别失败则停止。更换 Wi-Fi 后需自行确认并修改范围；扫描过程中不主动跟踪 Wi-Fi 切换。单个 TCP 路径错误不会触发全局停止，ICMP 系统错误仍会中止扫描。
- 使用 ICMP 数据报套接字和 TCP；对已配置且开放的端口分别发送 HTTP/HTTPS `HEAD /` 请求，收到有效 HTTP/1.0 或 HTTP/1.1 状态行后，仅当根路径提供可浏览页面才收录为 Web 资产：2xx 且为 HTML、带有效 `Location` 的 3xx、带 `WWW-Authenticate` 的 401，或任意状态码但页面含 `<title>`；403/404/5xx 且无 HTML 页面、返回 JSON 等非页面内容、以及 `Server` 为 AirTunes（AirPlay）的服务不作为 Web 资产，其端口仍保留在主机开放端口中。旧历史记录保持原样显示。HEAD 限时 2 秒、最多读取 16 KiB；确认后发送 `GET /` 提取页面信息，限时 3 秒、最多读取 64 KiB（含响应头），取得标题即停止。GET 失败仍保留 HEAD 识别结果。HTTP 返回 400 且页面标题明确匹配 Nginx 的“The plain HTTP request was sent to HTTPS port”提示时，不将该 HTTP 地址收录为 Web 入口；普通 400、正常 HTTP/HTTPS 双协议入口保持原逻辑，旧历史需重新扫描才应用此规则。不跟随重定向、不携带凭据；HTTPS 在扫描连接内评估证书，但允许自签名、不受信任或 IP 不匹配的证书继续握手；仍需有效 HTTP 响应才确认服务。校验未通过时在结果及历史中标注，旧记录无此标记。此行为仅用于扫描探测，不修改系统信任或浏览器校验；需要特定域名、客户端证书或不兼容 TLS 的服务仍可能无法确认。未确认不代表不存在 Web 服务。
- 扫描页“已发现资产”区域通过“IP”和“Web”分段 Tabs 切换；Web资产展示页面标题、服务地址、协议、状态码，以及响应提供的服务器和跳转地址，可点击打开原地址。标题缺失时以地址兜底；支持分块传输和常见 HTML 字符实体，不执行 JavaScript、不解压忽略 identity 请求而返回的压缩内容，部分编码或动态页面可能无法提取标题。新扫描会清空本次结果。Web 识别计入扫描进度，支持停止及进入后台取消；信息随扫描历史保存，历史详情使用相同的资产 Tabs，旧历史不会自动补充新信息。
- 不包含 mDNS、主动 ARP 扫描、MAC/厂商识别或完整拓扑。Ping 校验来源 IP、标识、序列号、随机负载及校验和，避免并发请求间串包。
- 不保证后台持续扫描，不启用背景模式。
- Simulator 编译只能验证代码；发现率、权限、Wi-Fi 路径必须真机测试。

## 真机验收

1. 在已知开放 80/443/22/445 之一的设备上验证“连接成功”。
2. 对明确拒绝连接的地址验证“有响应证据”。
3. 对不响应的测试地址验证扫描结束且不产生在线误报。
4. 扫描中停止、立刻再次开始，确认旧结果不进入新会话。
5. 拒绝局域网权限，确认出现权限诊断或检查权限的提示而不是“全部离线”；直接 TCP 模式的单端口权限错误应继续扫描。在开始前关闭 Wi-Fi，确认接口准备失败并停止。
6. 扫描中切到后台，确认扫描停止；回到前台可以重新开始。
7. 输入非法地址、公共地址或 /16，确认在发起连接前拒绝。
8. 分别在 /24 和非 /24（如 /23）的 Wi-Fi 下，对照系统地址与掩码验证自动网段；在 /16 下确认展示真实范围并提示手动缩小。
9. 直接修改自动填入的网段，确认重新进入前台、切换 Wi-Fi 和开始扫描不会覆盖输入，扫描及历史使用修改后的范围。
10. 在首次识别完成前输入或输入后清空网段，确认迟到的识别结果不会覆盖用户操作；终止并重新启动 App 后会重新尝试初始识别。
11. 无 Wi-Fi、仅蜂窝或仅 IPv6 时确认识别失败提示，不使用旧网段或示例网段。
12. 默认设置下，对可 ping 和禁止 ping（但 TCP 可访问）的设备抓包，确认只有前者收到指定端口的 TCP 探测；关闭筛选后两者均收到 TCP 探测。
13. 对 ping 成功但 TCP 全部未响应的设备确认仍显示主机和 Ping 结果，不显示端口行或空端口占位；配置多个端口，确认全部指定端口均被检查，实时结果和历史详情仅显示连接成功的开放端口；全部端口拒绝连接时仍保留主机和 Ping 结果，不显示端口行。检查旧版单端口历史中的拒绝连接记录也已隐藏。
14. 保存自定义端口及筛选开关，终止并重启 App，确认设置保留；取消修改不保存；空列表、0、65536、非数字输入应报错，重复端口只检查一次。
15. 在 ping 和 TCP 阶段分别取消/切后台，确认探测停止；立即重新扫描，不应混入旧回调。历史应保留当次设置和已获得的部分结果。
16. 在 Ping 筛选和直接 TCP 两种模式下扫描包含本机的 /24，确认不向本机发送 ICMP/TCP 探测、不显示本机结果，进度和历史总数均为 253；扫描不包含本机的范围时总数不减少。输入本机 IP 的 /32，确认显示没有其他地址并立即结束。
17. 首次进入扫描页允许使用期间定位和精确位置，确认显示当前 Wi-Fi 名称，扫描历史保存当次名称；换网返回后页面刷新名称、输入网段保持不变，旧记录仍显示原名称。拒绝定位或关闭精确位置后仍可扫描，页面仅显示“Wi-Fi”，新记录显示“未记录 Wi-Fi”。等待授权/名称读取时停止或切后台，确认迟到的回调不会启动扫描或污染下一次记录。
18. 检查今天、昨天、更早分组的名称与时间同行显示；使用长 Wi-Fi 名称和大字体检查时间可读、名称截断，完整名称可在详情查看。
17. 验证 TCP 的 `.failed(EPERM)`、`.waiting(EPERM)`、`EACCES` 和其他路径等待超时：当前端口记录为“探测错误”，剩余端口和其他地址继续，最终进度达到总数并保留诊断。明确拒绝仍记录为“拒绝连接”，拒绝连接、普通超时和探测错误的端口行均隐藏，错误不应单独产生已发现主机。
